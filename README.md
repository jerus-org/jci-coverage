# jci-coverage

Complexity and CRAP scores for [`cargo-llvm-cov`](https://crates.io/crates/cargo-llvm-cov)
coverage reports, with upload to [OtterWise](https://getotterwise.com) for code quality reporting.

[![License](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue.svg)](#license)
[![OtterWise Coverage](https://img.shields.io/endpoint?url=https://otterwise.app/badge/github/jerus-org/jci-coverage/coverage/9a4ad122-de69-4113-98ac-1358c62d545f)](https://otterwise.app/github/jerus-org/jci-coverage)

This is a Cargo workspace. The published crate lives in
[`crates/jci-coverage`](crates/jci-coverage) — see its
[README](crates/jci-coverage/README.md) for installation, usage, and the runtime
prerequisites.

> **Status:** early (0.0.x, pre-pre-release). `complexity` and `upload` are implemented,
> and the `jerus-org/jci-coverage` CircleCI orb is generated from them and published. See [ROADMAP.md](ROADMAP.md) for the phased plan.

## Why

- `complexity` computes cyclomatic complexity for the Rust functions in a Cobertura or lcov
  report (from `cargo llvm-cov`, which your own job runs) and writes it into the report, so OtterWise can show Complexity and CRAP scores.
- `upload` is a standalone, language-agnostic subcommand: it posts a coverage file to
  OtterWise. It does not require Rust or `cargo-llvm-cov` — a non-Rust
  project can use it on its own, against a coverage report generated by whatever means
  it already uses. It must run in a CircleCI job: OtterWise shows only uploads that carry a
  CI identity, so without the CircleCI environment `upload` stops and names what is missing.

## Development

```bash
just test        # clippy + check + doc + tests
just audit       # cargo deny (advisories, bans, licenses, sources)
just msrv        # verify the declared MSRV builds
just fmt         # nightly rustfmt (+ stable check)
just licenses    # regenerate THIRD-PARTY-LICENSES.md (cargo-about)
```
